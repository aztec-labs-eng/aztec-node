## Releases

Releases are driven by git tags. Each branch's version is tracked in its `.release-please-manifest.json` at the project root. Tags are created exclusively by the [release tag workflow](./.github/workflows/release-tag.yml) and the [release PR workflow](./.github/workflows/release-pr-tag.yml), both through the release GitHub App — a ruleset blocks anyone else (admins included) from creating `v*` tags. Nightly tags (`v<ver>-nightly.<date>`) are cut every night for each branch in the workflow's matrix; a release candidate (`v<ver>-rc.<n>`, with `n` auto-incremented from origin's existing rc tags) is a manual dispatch with `kind=rc`; a real release (`v<ver>`) is a manual dispatch with `kind=release`. Both rc and release dispatches pause for a second person's approval. A new tag triggers the [release workflow](./.github/workflows/release.yml), which runs `./bootstrap.sh release` to build and publish the version at that tag: npm packages to npmjs, docker images to DockerHub, and the aztec-up and playground assets to S3. The `ci-release-pr` label on a pull request cuts a canary release the same way: `v<ver>-commit.g<sha>` at the PR head, released like any other tag, with the `commit` channel keeping it off the shared npm dist-tags.

A *private release* publishes the same version to the Labs-owned GCP Artifact Registry instead, and publishes nothing public. It is a manual dispatch of the release tag workflow with `kind=private`, gated by the same second-person approval as an rc, which cuts the tag `private/v<ver>-private.<n>`. That tag triggers the [private release workflow](./.github/workflows/private-release.yml), which runs the same `./bootstrap.sh release` under `RELEASE_TARGET=private`: the `@aztec-foundation` packages it builds against and the `@aztec-labs` packages it publishes both come from and go to the Artifact Registry npm repo, and the docker images go to the Artifact Registry docker repo. The `private/` prefix is part of the ref, not the version: it is what routes the tag to this workflow and to the `release-private` environment, which holds the Artifact Registry credential and nothing that can publish publicly — while the `release` environment holds the npmjs and DockerHub credentials and nothing that can read the Artifact Registry. A job declares one environment, so no run can read from one side and publish to the other. Private releases skip `aztec-up` and `playground`, whose artifacts are public by nature, and upload nothing to the build cache, which is world-readable.
