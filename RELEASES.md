## Releases

Releases are driven by git tags. Each branch's version is tracked in its `.release-please-manifest.json` at the project root. Tags are created exclusively by the [release tag workflow](./.github/workflows/release-tag.yml) and the [release PR workflow](./.github/workflows/release-pr-tag.yml), both through the release GitHub App — a ruleset blocks anyone else (admins included) from creating `v*` tags. Nightly tags (`v<ver>-nightly.<date>`) are cut every night for each branch in the workflow's matrix. A manual dispatch with `kind=nightly` cuts one on demand, for a day the cron missed or botched; it takes an optional `suffix` (`v<ver>-nightly.<date>.<suffix>`, 1-20 lowercase letters, digits and hyphens starting with a letter) so a re-cut does not collide with a tag the cron already pushed. The suffix is its own prerelease identifier, so the release channel stays `nightly` and the tag sorts after the day's scheduled one. Scheduled runs never carry a suffix, so the plain date tag remains what scheduled consumers resolve. A release candidate (`v<ver>-rc.<n>`, with `n` auto-incremented from origin's existing rc tags) is a manual dispatch with `kind=rc`; a release candidate (`v<ver>-rc.<n>`, with `n` auto-incremented from origin's existing rc tags) is a manual dispatch with `kind=rc`; a real release (`v<ver>`) is a manual dispatch with `kind=release`. Every dispatch pauses for a second person's approval, a nightly re-cut included; the cron is the only unattended path. No dispatch ever moves an existing tag: a run whose tag is already on origin fails instead of retagging. A new tag triggers the [release workflow](./.github/workflows/release.yml), which runs `./bootstrap.sh release` to build and publish the version at that tag: the aztec-nr crates as a tagged snapshot on the [aztec-nr mirror](https://github.com/aztec-labs-eng/aztec-nr) (which `aztec init` pins), npm packages to npmjs, docker images to DockerHub, and the aztec-up and playground assets to S3. The `ci-release-pr` label on a pull request cuts a canary release the same way: `v<ver>-commit.g<sha>` at the PR head, released like any other tag, with the `commit` channel keeping it off the shared npm dist-tags.
