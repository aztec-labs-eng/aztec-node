Owns where the binaries labs components build with come from, so those components work the same in the monorepo and in a split labs repo.

`bootstrap.sh` pins a bb and a noir version and provisions `bin/`: `bb` and `bb-avm` from the `@aztec-foundation` npm packages the foundation publishes, curled as plain tarballs rather than installed through a package manager (`bb-avm` is published for linux only); and `nargo`, `noir-execute` and `noir-profiler` out of the noir release archive for the machine's target triple, curled the same way. `bb-avm` is optional on a developer machine that cannot provision it, but required when `CI=1`. `bin/.pin` records what was installed and is what makes a re-run incremental.

To provision the optional prover-agent binary, set `BB_BOOSTED_URL` to an immutable URL for the build host's OS and architecture (a raw executable or a `.tar.gz` containing `bb` at its root), then run `labs-aztec-toolchain/bootstrap.sh`. Leave it unset or empty to skip the download. Both provisioning modes install it as `bin/bb-boosted`. Release images include it when present and preset `BB_BOOSTED_BINARY_PATH` to `/usr/src/labs-aztec-toolchain/bin/bb-boosted`. Set `BB_USE_BOOSTED=true` on the prover agent to use it. Outside a release image, also set `BB_BOOSTED_BINARY_PATH` to the installed executable. Leave `BB_BINARY_PATH` unchanged.

The pinned versions are also copied into manifests that cannot read them from here (e.g. `Nargo.toml`): `pins.mjs` lists those files. `./bootstrap.sh set-pins <bb-version> [noir-version]` bumps this file and every copy, and every pinned-mode build fails on drift. `./bootstrap.sh use-local <foundation-root>` instead points each copy that has a local form at a foundation checkout, and records the root in `.fnd-root` so builds provision `bin/` from the same checkout - the foundation repo applies it to its labs submodule's worktree after each submodule update and never commits the result.

Consumers take `NARGO`/`BB` from `bin/`, the toolchain identity from `bootstrap.sh hash` (for cache keys), and the pinned noir version from `bootstrap.sh noir_version`.
